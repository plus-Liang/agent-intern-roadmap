# 项目复盘：学习/实习规划助手

## 一、需求来源

我自己要从零基础转 Agent 开发，需要一个可执行的实习准备计划。
手动规划的问题：

- 容易漏掉关键环节（Git、README、部署）
- 时间分配不合理，前期学太多理论、后期来不及做项目
- 计划改了之后，之前的版本散落在各处，难以对比

所以我做了这个工具，核心目标：**输入个人情况，输出可执行计划，支持随时追问调整。**

## 二、方案设计

### 整体架构

```text
用户输入（目标/时间/基础）
  ↓
Prompt 构造（prompts.py）
  ↓
调用 ARK API（llm_client.py）
  ↓
流式返回 → 界面渲染（app.py）
  ↓
保存对话（storage.py）
```

### 模块划分

| 模块 | 职责 |
|---|---|
| `prompts.py` | 只负责 Prompt 模板，不管调用 |
| `llm_client.py` | 只负责 API 通信、重试、流式 |
| `storage.py` | 只负责保存文件 |
| `errors.py` | 定义异常类型 |
| `logger.py` | 日志配置 |
| `app.py` | 界面与流程控制 |
| `main.py` | CLI 版本 |

**为什么这样分**：每个文件只做一件事，出问题能快速定位；换 API 平台只改 `llm_client.py`；换界面只改 `app.py`。

### 关键设计决策

1. **消息历史全部发送**

   模型本身无记忆，每轮把 `messages` 完整发给 API，模型才能"记住"之前的内容。

2. **输出模式状态机**

   - 默认 `diff`：只输出改动，节省 token，方便快速看变化
   - 用户显式要求 `full`：输出完整计划，方便整体替换
   - 用 `session_state` 记录模式，隐式追问保持模式，只有用户明确指令才切换

3. **流式输出**

   首字延迟从 30 秒降到 2–5 秒，用户体验完全不同。

4. **异常分层**

   - `ConfigError` 不重试，直接告诉用户改配置
   - `APIError` 重试 3 次，等待时间递增
   - 配置检查延迟到调用时，避免 import 阶段崩溃

## 三、遇到的问题与修复

### 1. 函数参数顺序错误

**现象**：文件名里是一大段计划，文件内容只有一句话。
**原因**：定义方 `save_plan(goal, content)`，调用方 `save_plan(answer, goal)`，位置对应错了。
**修复**：统一为 `save_plan(content, goal)`。
**收获**：Python 按位置传参，不看名字。顺序必须一一对应。

### 2. 配置异常接不住

**现象**：删掉 Key 后运行，直接 Traceback，没有走 `try/except`。
**原因**：`raise ConfigError` 写在模块顶层，`import` 时就抛，`main()` 里的 `try` 还没执行。
**修复**：把检查移到 `_get_client()` 函数内部，调用时才抛。
**收获**：`try` 只能接住"它执行之后"抛出的异常。import 阶段的异常发生在 try 之前。

### 3. 非流式太慢

**现象**：要等 30–60 秒才看到内容。
**修复**：改用 `stream=True`，逐字返回。
**收获**：流式不只提升速度感受，中途断网也能看到已生成部分。

### 4. Streamlit DOM 冲突

**现象**：流式输出时浏览器报 `removeChild` / `insertBefore`。
**原因**：`st.write_stream` 动态创建/销毁容器，和 Streamlit 的 rerun 机制冲突。
**修复**：改用 `st.empty()` 固定容器 + 手动 `markdown` 覆盖。
**收获**：第三方框架的 bug 不一定要根治，换稳定的 API 更实际。

### 5. 追问框不显示

**现象**：生成计划后，底部没有输入框。
**原因**：`st.chat_input` 在 `if/else` 分支里，点按钮那轮走 `if` 分支，Streamlit 不会自动重跑。
**修复**：把 `chat_input` 独立成一段，用 `if started` 控制显示。
**收获**：Streamlit 每次交互只跑一遍脚本，条件渲染要放在顶层。

### 6. ARK API 首次超时

**现象**：第一次请求 30 秒超时，重试后成功。
**修复**：`timeout` 改 90 秒，配合重试机制。
**收获**：接入点冷启动是常见现象，重试机制能兜住。

## 六、面试可讲的点

### 问题 1：RAG 检索不准怎么排查？

> 我在另一个项目（Dify RAG）里遇到检索不召回的问题。
> 排查顺序：先看知识库分段数，发现默认切块把 8 条 JD 切成 210 段，语义过碎；重新切块降到 17 段后，召回测试正常但 Agent 仍说"未找到"；再看 LLM 节点 prompt_tokens 只有 138，说明检索结果没进 Prompt；根因是 Prompt 变量手写节点名，Dify 解析不到；改用变量面板点选后，prompt_tokens 涨到 2500+，回答正常。

### 问题 2：Agent 为什么会乱调工具？

> 我理解 Agent 的工具调用依赖模型自主判断，稳定性不如工作流。
> 在"确定性任务"（如 JD 整理）上，我会用 Chatflow 把检索设为强制节点，不依赖模型决定。
> Agent 更适合开放式任务，比如项目三里要做多步骤调研。

### 问题 3：你如何测试？

> 我准备了 5 类测试问题：明确可答、需要对比、需要统计、资料里没有、模糊歧义。
> 每类记录：是否答对、是否引用、是否编造、失败原因。
> 比如问"有没有远程实习"，模型应该明确说"资料中未找到"，而不是编一个。

### 问题 4：你负责了什么？

> 独立完成了整个项目：需求定义、模块拆分、API 封装、异常处理、Web 界面、文档。
> 关键决策：消息历史全量发送、输出模式状态机、流式输出替代一次性返回、异常分层处理。
