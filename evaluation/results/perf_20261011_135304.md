## 结论

- 最快：**追问**（未命中缓存的 min 中位 3.98s）—— 不重新检索，从会话态 last_job_list 取序号 → 读 JD → 带引用作答
- 最慢：**匹配打分**（中位 81.82s）—— 原因：要读 JD + 打分 + 反思，反思判不合理还会再打分一次，LLM 轮次最多
- 最贵来源：**rag_citation_faithfulness**（平均 2962 token/次，占 37.8%，约 0.0030 元/次）
- 优化方向：给最慢的那条链路加**结果缓存 + prompt 瘦身**（相同「岗位 JD + 简历」组合缓存打分结果；面试 prompt 里的 JD 截到要点）。**本轮不做**：当前目标是先量准现状、留一条可复现的基线，加缓存会改变这几组数字的语义、口径要先对齐；且单 worker 下没有并发压力，省下来的是延迟而不是吞吐。
